# Pivloom E2E 测试规格

版本：2.0 · 2026-09-23。当前复核以[上游复用技术方案](specs/technical-recheck-v2.md)为准。覆盖全新计算器/Canvas贪吃蛇、两轮增量、跨会话/账号隔离、版本回滚、生命周期故障和部署SHA。

本版更新E04/E05/E08/E09/E12的应用与断言，新增E32–E42、I13–I22。旧报名/书单的PASS仅是历史证据，不能自动转成新版PASS。历史报告见[主链路](test-runs/2026-09-23-finalization.md)、[前端](test-runs/2026-09-23-frontend-refresh.md)、[永久发布](test-runs/2026-09-23-publication.md)。

**本轮产品改造与新版产品E2E均为NOT_RUN。** Pi的45个上游离线测试、5个SDK探针和agent-browser原版9个本地动作已有单独证据，只证明可复用接口，不证明真实Provider视觉能力或生产端到端通过。

每模块完成立即跑关联用例；全部模块通过后冻结同一组Web/API SHA再做整链。失败保留原始证据和版本，不能通过改数字、删旧要求、换预制应用或强制DOM棋盘取得通过。

## 1. 测试策略

开发与正式UI验收优先使用Codex内置浏览器（iab），在旁边实际操作登录、工作台、Preview、小游戏和回滚。产品内部Reviewer是在服务器OpenSandbox中用Chrome/agent-browser自动检查，两者必须是不同会话。仅在IAB故障或用例需要其当前不提供的独立会话能力时，使用固定版本agent-browser作为独立QA补充，并记录原因；不把新标签当新会话，不把产品自身Check当独立QA。Canvas指生成应用的HTML画布，不是一种浏览器。

| 层次 | 采用的成熟能力 | 证明范围 |
|---|---|---|
| 上游兼容探针 | Pi官方离线测试/SDK示例；agent-browser原生press、wait、batch、screenshot | 版本与接口可用，不证明真实Provider/业务通过 |
| 独立UI E2E | 优先Codex内置浏览器，从登录开始，真实按钮、键盘、Canvas截图及刷新 | 用户主流程；禁止注入分数、坐标、源码或测试数据绕过页面 |
| 产品Reviewer | OpenSandbox内agent-browser + Pi ImageContent + 实测有图像能力的Provider | 同一候选的DOM、截图、动作和检查；图片只存档不算模型看过 |
| 服务集成 | 现有Vitest/PostgreSQL；关键取消/销毁接真实OpenSandbox | 事务、幂等、取消竞争、事件顺序、会话撤销与清理确认 |
| 静态与产物 | 类型、lint、构建、冻结SHA/manifest | 来源和兼容性，不能替代UI或真实生成 |

复用上游测试先读断言，测试名不等于覆盖范围。假LLM、脚本模型、故障产物必须标注fixture，不能证明非固定模板生成。游戏recipe的时间/文本状态接口只能辅助，真实输入、截图和业务结果仍必测。按既有技术栈使用agent-browser，不为复制一份Playwright样例而替换产品浏览器。

## 2. 环境、身份、数据与前置门槛

### 2.1 三种测试环境

| 环境 | 用途 | 约束 |
|---|---|---|
| Local/isolated test | 开发与可重复故障 | 经统一代理访问，如已配置的 `http://localhost:8080`；测试数据库、测试账号；允许维护脚本注入故障 |
| Staging | 接真实模型/OpenSandbox/Supabase 的完整联调 | HTTPS 与正式拓扑一致；合成数据；故障测试不得影响正常评审 |
| Online Demo | 发布候选的最后核验 | 故障注入关闭；使用提供给评审的入口；只做正常流程和明确允许的测试项目操作 |

每份测试报告必须填写真实 URL、build commit/版本、API boot ID、模型 profile、沙箱镜像digest、浏览器环境和测试时间。已部署环境以各次实测记录为准；示例地址本身不证明服务可用或公网交付完成。

### 2.2 账号

测试基础设施由开发代理在已授权服务器部署自托管Supabase并生成服务URL/密钥，执行迁移、私有bucket、幂等A/B身份、测试前缀/manifest和精确清理。用户模型通过页面配置；Pi、沙箱与Supabase仍须联合验证。开发期使用localhost/SSH隧道，不要求域名；公网HTTPS阶段另测。见[基础设施分工](infrastructure-setup.md)。

- `tester-A`：普通评审账号，拥有测试项目；凭据由安全配置提供，不写进文档或截图。
- 测试B：不同owner，优先在同构隔离环境准备临时身份并精确清理。生产曾要求只保留A，旧B已删除，不能复用旧账号或自动恢复生产旧数据。
- 维护脚本身份：仅隔离测试环境，用于 seed、故障设置、检查数据库和清理。它不是浏览器用户，也不作为产品 API 暴露。

两个浏览器标签通常共享登录态。不能假设新标签等于独立浏览器 context。隔离测试可顺序登录 A/B，在退出时确认状态清空；多标签并发测试使用同一个 A。需要不同账号同时在线时只能使用工具明确支持的独立会话能力，否则用集成测试补证，不能臆造 incognito/context API。

### 2.3 真实生成需求 A：计算器与两轮增量

三个Prompt原样保存，在同一个全新项目依次提交；修复attempt不算用户追加修改。

首次需求A0：

> 做一个中文计算器网页，从空业务工程实现。支持数字、小数、加减乘除、括号和标准运算优先级；有清空、退格、等号按钮，也能用键盘数字、运算符、Enter、Backspace、Escape操作。除零和无效表达式有明确提示，清空后能继续计算。显示当前表达式和结果，手机窄屏按钮可操作。不要预写测试答案，不使用现成计算器页面。

功能增量A1：

> 在这个计算器中增加计算历史：记录算式和结果，可从历史重用结果，并有清空历史操作。当前浏览器刷新后历史保留。保留原来的四则、括号优先级、小数、键盘、清空退格、错误提示和恢复功能。

视觉增量A2：

> 保留全部功能和计算历史，把页面改为深色背景、橙色运算键、等宽结果区；调整键盘间距和字号，使390px宽度下无需横向滚动且所有按键可用。只改变这里明确提出的视觉要求，不删减已有功能或校验。

固定断言：2+3×4=14；(2+3)×4=20；0.1+0.2合理显示0.3；12退格后为1；8÷0不能成为伪正常结果；错误后清空再算5×6=30；通过键盘完成另一算式。A1/A2追加历史记录、重用、清空和同origin刷新保留。每轮重测此前全部断言，不以当前计划只保留几项为理由省略。

### 2.4 真实生成需求 B：Canvas 贪吃蛇

在另一个全新项目提交，不加载计算器或旧报名/书单业务源码：

> 做一个中文贪吃蛇小游戏，使用Canvas绘制棋盘、蛇和食物。方向键四向控制，不能立即反向穿过自己；支持开始、空格暂停/继续、游戏结束后重新开始。吃食物时蛇变长且分数增加，碰墙或撞到自己结束；显示当前分数、最高分和操作说明，最高分在同一浏览器刷新后保留。不要提供测试专用加分、改坐标或跳过碰撞按钮。

实际操作：启动看到蛇/食物；四向键盘改变运动；反向输入不穿过身体；通过观察画面和实际移动吃到至少一个食物；长度与分数变化；暂停画面保持、继续恢复；碰墙、自碰结束；重开当前分数/棋盘恢复，最高分按约定保留。

可用原生batch执行短动作后通过正常暂停稳定画面，再送截图给模型继续决策。只检查HUD文本、读源码、存截图或脚本改状态不证明Canvas行为。图像Provider门槛不通过则BLOCKED并解决，不能改成DOM版或旧书单替代。

### 2.4.1 每轮五项检查与完整回归

用户已确认：运行前固定五个验收组，每组列完整子断言。计算器五组为数值运算、输入编辑与键盘、错误恢复、结果状态/历史、视觉布局；贪吃蛇五组为画面启动、方向控制、吃食增长计分、暂停/碰撞状态、重开/最高分/布局。每组全部子断言通过才可为passed，增量只能追加或按用户明确变更替代子断言，不能悄悄删旧required或复用ID改义。

保留产品原始Check和真实数量。若产品尚未支持约定的组/子断言映射，不能在报告把N/N重写成产品5/5，视为该展示契约尚未满足。固定五组是本轮场景约定，不把所有用户项目强制限制为五个需求。

每轮证据元组：projectId、runId、baseRevisionId、revisionId、revisionNo、sourceHash、Check ID、Preview marker、模型profile/configVersion及实际model ID、Web/API SHA。角色用量与脱敏传输证明真实模型调用；可读源码diff证明实际修改，二者不互相替代。

### 2.5 开测前清单

1. 固定Pi 0.86.1、产品agent-browser 0.38.1、OpenSandbox SDK/镜像及Node 24+；记录独立QA浏览器实际版本。先完成E32/E33/E34所需门槛，服务健康、迁移版本正确。
2. A/B 身份已准备、测试项目有独立前缀，模型有足够测试额度，OpenSandbox通过容量门槛且有可分配资源。
3. 正常用例关闭 fake runner 与故障 profile；有明确 build 与配置记录。
4. 用例涉及维护脚本时先在隔离环境预设故障，再由 UI 触发真实流程。
5. 每个测试项目的活动 run、sandbox、revision 能由维护者关联查询；查询结果要脱敏。

不满足前置条件记 BLOCKED，记录原因；不能改成全 mock 跑一遍后宣布实际链路通过。

## 3. 独立浏览器执行规程

- IAB使用当次工具文档；独立agent-browser使用固定版本和唯一session。QA A、QA B、全新会话、产品Reviewer分开，不加载旧认证state。
- 先open/snapshot取得当前refs，再click/fill/press；页面变化后重新snapshot。不需要中间决策时使用上游batch JSON argv数组，错误停止并读取结果。
- 等待页面状态、Run阶段或事件；动态游戏用短动作burst后重新截图。不用无限networkidle等待SSE页面，不靠长sleep碰阶段。
- 截图、Console/PageError、网络结果、Preview marker和源码版本一起保存。截图成功不等于模型已收图，E33单独证明。
- QA可读取DOM、尺寸和服务端补证，不能设置应用状态伪造交互。登录通过UI完成，后台Auth只作补证。
- 工具超时先确认同一会话/Run是否仍活跃；不能因观察超时重复提交生成。工具失效才换浏览器，并记录切换。
- 结束仅清理本轮QA会话及manifest列明资源，保留A正式作品。

## 4. 发布关键路径用例

下面 E 用例中的“通过”是判定标准，实际结果以开头链接的逐模块报告为准；没有实测记录的项目为 **NOT_RUN**。`证据` 中的服务器查询是补证，与 UI 操作结果分别记录。

### E01 · 登录与进入项目列表 · P0

- 前置：Online Demo 或 staging，A 无登录态。
- 步骤：通过 UI 输入 A 的账号密码并登录；确认项目列表；刷新；退出；再次打开原受保护 URL。
- 通过：登录后进入自己列表，刷新正常；退出后回登录且不显示缓存项目内容。密码不出现在 URL、日志或报告截图。
- 证据：登录后/退出后页面状态；401/身份验证集成结果另见 I09。

### E02 · 错误账号、过期身份 · P0

- 前置：隔离账号；维护者可使测试 session 失效。
- 步骤：输入错误凭据；更正后登录；使身份失效；尝试读取项目和发送新需求。
- 通过：通用错误提示；正确登录可恢复；过期身份刷新失败后要求重登录，没有未经授权的新 run；未接受的草稿保留。
- 证据：可读错误与任务计数；不能仅因按钮灰掉就断言后端拒绝。

### E03 · 空项目、输入边界与中文输入 · P0

- 前置：A 登录，容量足够。
- 步骤：新建项目；查看空态；提交空格/超 8,000 字符内容；输入中文并用输入法确认候选；Shift+Enter 换行；准备合法需求。
- 通过：项目生成独立 URL；非法输入不产生 run；输入法确认不误发，换行与发送规则正确；示例按钮只填文本。
- 证据：空态/字段提示和数据库中无多余 run。不要通过 DOM 注入超长值，使用正常输入操作。

### E04 · 全新计算器真实生成 · P0

- 前置：空project，无currentRevision或业务seed；真实Provider/OpenSandbox，TEST_PROFILE与产物adapter关闭。
- 步骤：UI发送A0一次，观察角色/工具，打开结果、源码和Preview。
- 通过：冻结模型配置、role用量与真实请求可关联；模型写完整计算器业务代码，真实构建、Check、current及Preview绑定一致。
- 证据：完整Prompt、project/run/role IDs、脱敏请求和完整源码manifest。通用脚手架可复用，预制计算器、硬编码测试答案不通过。

### E05 · 计算器完整业务行为 · P0

- 前置：E04结果。
- 步骤：通过UI操作2.3全部四则、括号、小数、退格、错误恢复、键盘断言。
- 通过：每项结果正确，无未捕获页面错误，不能只证明一个加法。
- 证据：具体输入、屏幕结果、截图和五组完整子断言；与产品Check分组逐项核对。

### E06 · 刷新、新标签、版本标识 · P0

- 前置：E04/E05 预览健康。
- 步骤：点击工作台刷新预览；点击新标签打开；通过 tab inventory 找到新增标签；比对版本与行为；返回工作台切换桌面/窄屏容器。
- 通过：都是所选 revision 对应构建；控件可用；没有意外打开旧版本。窄屏切换不重新生成应用。
- 证据：实际 URL、revision 标识、两处渲染；新标签用完关闭本次创建的标签。

### E07 · 真实源码查看 · P0

- 前置：已保存版本。
- 步骤：打开代码页签读取业务入口和样式；后台补证下载该revision全部文件，检查完整路径集合、逐文件hash和可读diff；刷新再打开。
- 通过：内容来自真实快照，能对应业务行为；只读，无虚假的保存代码按钮；依赖/环境密钥未展示。
- 证据：文件路径/hash 摘要。任意路径与他人快照访问由 I09 额外验证。

### E08 · 同项目功能增量 · P0

- 前置：E04/E05通过，保存完整源码和基线断言。
- 步骤：同project发送A1；运行中查看旧版本；新版本操作历史记录、重用结果、刷新保留和清空，再跑A0全部断言。
- 通过：project不变、baseRevision正确；新增历史实际工作，旧required全部保留；diff包括实际业务代码。
- 证据：完整manifest、可读diff、原始Check和Preview marker；不能仅用hash变化证明增量。

### E09 · 同项目视觉增量 · P0

- 前置：E08通过。
- 步骤：同project发送A2；桌面和390px真实视口检查配色、等宽结果区、字号间距；重测A0/A1全部行为。
- 通过：视觉变化实际呈现，无横向溢出/遮挡；算术、键盘、错误恢复和历史完整保留。
- 证据：前后截图、实际尺寸、全量回归、源码diff；CSS字符串/hash不能单独证明视觉通过。

### E10 · 生成中刷新工作台 · P0

- 前置：一次正常真实修改已被接受，尚在执行。
- 步骤：记下 run ID；刷新工作台；观察恢复；等待结果；检查聊天和角色活动。
- 通过：恢复同一 run；用户消息、模型任务和结果各一份；状态最终收敛，不倒退到开始，不重新 POST。
- 证据：刷新前后同一 run ID；I01/I04 对请求和事件去重补证。

### E11 · 全新浏览器与退出重登 · P0

- 前置：A2完成，记录项目、完整对话、全部版本和完整源码manifest。
- 步骤：原会话退出重登；另开没有认证与存储的独立浏览器，从UI登录A，再打开项目/历史/源码/Preview，按需恢复预览。
- 通过：五类平台数据逐项一致；恢复模型调用计数不变；新标签/新HTTP token不算新浏览器。
- 证据：两独立会话、UI登录、对话/文件清单对照；新浏览器localStorage为空不能误判平台数据丢失。

### E12 · 全新 Canvas 贪吃蛇与非模板验证 · P0

- 前置：E33/E34通过，计算器保留；另一个空项目，无业务seed。
- 步骤：UI发送2.4原始Prompt，走真实模型；独立浏览器实际四向、吃食、暂停/继续、碰撞、重开、最高分，再返回计算器。
- 通过：真实Canvas小游戏和计算器有不同业务实现；图像/按键支持全部检查；计算器源码、对话和current不变。
- 证据：两项目真实模型/工具记录、文件内容差异、gameplay阶段截图和HUD；旧书单、DOM替代、预制Snake或改分数不通过。

## 5. 异常与恢复用例

### E13 · 模型阶段停止 · P0

- 前置：隔离环境 `SLOW_MODEL`，或真实足够长的生成；报告区分二者。
- 步骤：分别等待Coordinator/Builder/Reviewer确定阶段gate后点击停止；重复点一次；刷新并等待终态与清理。
- 通过：先显示正在停止，Run最终为cancelled而非failed；await Pi abort/idle后收口，迟到工具仍见取消；远端/DB确认后释放，current不变，重复停止幂等。
- 证据：UI 终态、Pi abort/信号记录；若用了 fake 慢响应，此用例不单独证明真实 provider 的中断，G0 要补一次真实流取消。

### E14 · 远程命令阶段停止 · P0

### 8.2 故障 profile 设计
