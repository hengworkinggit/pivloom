# Pivloom E2E 测试规格

版本：1.0 · 2026-09-22。范围：[PRD F01–F14](PRD.md)，实现契约：[TRD](TRD.md)。

**当前产品尚未实现，本文所有产品用例均为 NOT_RUN。** 第 11 节的 PASS 仅指 Codex 内置浏览器在独立夹具上的能力探针。测试方案、用例和门槛已定义，不能据此声称 Demo 可用或已经完成验收。

## 1. 测试策略

用户流程的主验收工具是 **Codex 桌面内置浏览器（`iab`）**。从登录到需求输入、预览内交互、持续修改、重新打开，都实际操作页面。页面源码、构建成功或产品自己的 Reviewer 报告，不能代替这层测试。

| 层次 | 工具 / 环境 | 能证明什么 | 不能替代什么 |
|---|---|---|---|
| 开发 UI E2E | Codex 内置浏览器 + 真实工作台 | 可见流程、iframe 操作、键盘、状态、错误、布局 | 不能仅凭截图证明后台取消/事务/隔离 |
| 产品内部检查 | E2B 中 agent-browser + Reviewer | 生成应用的限定行为检查和修复反馈 | 不能验收 Pivloom 登录、工作台、SSE 或公网代理 |
| 服务集成测试 | 测试 runner + Postgres + adapter；关键操作接真实 E2B | 幂等、状态竞争、owner 权限、远端清理、数据一致性 | 不能把 API 返回成功记成 UI 流程成功 |
| 静态与构建检查 | 类型检查、lint、production build | 基本类型、导入、构建 | 不证明点击、保存或持续修改有效 |

不把外部 Playwright 测试进程作为默认 UI 验收入口。Codex 工具内部可能将语义定位对象命名为 `playwright`；使用它仍是在 Codex 内置浏览器当前页面操作，不是另外启动浏览器或安装测试 runner。优先使用实际 AX 状态；复杂 iframe 可用工具已公开的语义定位能力。

内置浏览器是一项桌面运行能力，目前不假定有无头 CI 调用接口。CI 可跑集成/类型/构建检查；发布前由 Codex 桌面执行 UI 用例，保留实际记录。不能把一段 CUA 调用示例包装为已经接入 GitHub Actions 的 E2E 套件。

## 2. 环境、身份、数据与前置门槛

### 2.1 三种测试环境

| 环境 | 用途 | 约束 |
|---|---|---|
| Local/isolated test | 开发与可重复故障 | 经统一代理访问，如已配置的 `http://localhost:8080`；测试数据库、测试账号；允许维护脚本注入故障 |
| Staging | 接真实模型/E2B/Supabase 的完整联调 | HTTPS 与正式拓扑一致；合成数据；故障测试不得影响正常评审 |
| Online Demo | 发布候选的最后核验 | 故障注入关闭；使用提供给评审的入口；只做正常流程和明确允许的测试项目操作 |

每份测试报告必须填写真实 URL、build commit/版本、API boot ID、模型 profile、E2B template、浏览器环境和测试时间。当前没有已部署 URL；示例 localhost 地址不是已经启动的产品。

### 2.2 账号

- `tester-A`：普通评审账号，拥有测试项目；凭据由安全配置提供，不写进文档或截图。
- `tester-B`：不同 owner，验证隔离；本轮没有团队管理员功能。
- 维护脚本身份：仅隔离测试环境，用于 seed、故障设置、检查数据库和清理。它不是浏览器用户，也不作为产品 API 暴露。

两个浏览器标签通常共享登录态。不能假设新标签等于独立浏览器 context。隔离测试可顺序登录 A/B，在退出时确认状态清空；多标签并发测试使用同一个 A。需要不同账号同时在线时只能使用工具明确支持的独立会话能力，否则用集成测试补证，不能臆造 incognito/context API。

### 2.3 真实生成需求 A：活动报名

首次需求（原样输入，测试日期后缀写在项目名，不改业务要求）：

> 做一个中文活动报名管理网页。包含姓名、邮箱、活动类别三个字段，活动类别为设计和开发。姓名和邮箱必填，邮箱格式不正确时显示错误。提交后报名记录出现在列表中，初始列表为空；每条记录默认待确认，可以点击确认变成已确认。支持按姓名或邮箱搜索。不要真的发送邮件。使用浏览器本地存储保存当前预览中的报名记录，不需要后端。界面清爽，表单和列表可直接操作。

追加修改 1：

> 在原项目增加报名状态筛选：全部、待确认、已确认。筛选应和原有搜索同时生效。保留新增、邮箱校验和确认报名的行为。

追加修改 2：

> 在原项目增加总报名数和已确认数统计，不随筛选而改变统计口径。改善 390px 窄屏布局，不出现整页横向滚动。保留之前所有表单、搜索、筛选和确认功能。

操作数据：

| 姓名 | 邮箱 | 类别 | 最终状态 |
|---|---|---|---|
| 林舟 | `linzhou@example.test` | 设计 | 待确认 |
| 田禾 | `tianhe@example.test` | 开发 | 已确认 |
| 宋宁 | `songning@example.test` | 设计 | 待确认 |

期望总数 3、已确认数 1；状态筛选已确认只显示田禾；搜索“林”并选择已确认时为 0 条；切回全部时为林舟 1 条。邮箱无效样本 `not-an-email`。

新 revision 可能有新预览 origin，故 localStorage 不承诺跨版本迁移。每轮修改验收在该版本重新通过 UI 录入这 3 条合成数据；不把清空业务数据误判为平台项目丢失，也不以此掩盖需求中的同来源刷新持久化失败。

### 2.4 真实生成需求 B：读书清单

> 做一个中文读书清单网页，初始没有书。可以输入书名和作者添加记录，书名必填。记录可标记为已读，支持按全部、未读、已读筛选，并显示总数和已读数。用 localStorage 保存当前浏览器的数据。不需要报名、邮箱或活动类别字段。

通过 UI 添加《海边的地图》/作者甲和《晨间笔记》/作者乙，将前者标为已读。期望总数 2、已读 1、已读筛选仅前者。这个需求必须重新走真实模型和工具，不能用 fixture project 代替。

### 2.5 开测前清单

1. G0 的 Pi/E2B/模型/Chrome 实际集成通过，服务健康，DB 迁移版本正确。
2. A/B 身份已准备、测试项目有独立前缀，模型和 E2B 有足够测试额度。
3. 正常用例关闭 fake runner 与故障 profile；有明确 build 与配置记录。
4. 用例涉及维护脚本时先在隔离环境预设故障，再由 UI 触发真实流程。
5. 每个测试项目的活动 run、sandbox、revision 能由维护者关联查询；查询结果要脱敏。

不满足前置条件记 BLOCKED，记录原因；不能改成全 mock 跑一遍后宣布实际链路通过。

## 3. Codex 内置浏览器执行规程

### 3.1 打开与观察

在 `mcp__cua_repl.js` 中使用当次已提供的 API。第一次选择浏览器只调用一个入口，例如在本地服务已实际启动的前提下：

```js
var testTab = await cua.createBrowserTab("iab", "http://localhost:8080", { visible: true });
```

读取工具返回的浏览器 ID、tab ID 和 UI 文档后继续。不沿用本文探针的 tab=2/browser=1；那只是历史会话编号。已有目标标签时先 inventory 再选择准确标签，避免无意义地重开。

```js
await testTab.getAXState();
// 依据这次观察到的输入框和按钮编号填写/点击。
// 每次页面改变后重新 getAXState，再选择下一步编号。
```

不要将预设数字当成跨页面 selector；不要用 shell、网络 API 或页面脚本直接设置应用 store 来代替 UI 操作。服务端 seed/reset 可用于准备测试环境，但必须在报告中标注，它不能取代 E04 的真实需求输入和生成。

### 3.2 iframe、语义定位与截图

AX 能展开 iframe 时直接操作其中节点。必要时获取实际 browser/tab 后使用已提供的 `domSnapshot()` 和 frameLocator；以下选择器依赖我们已实现的 iframe title，必须先在当前页面观察到：

```js
// richTab 是工具文档允许的当前 Tab 对象。
var preview = richTab.playwright.frameLocator('iframe[title="应用预览"]');
// 先 snapshot 确认实际按钮名称，再 getByRole(...).click()。
```

每个关键业务动作后同时确认可见结果，而非只记录 click 没报错。关键点截图：初次可操作结果、两轮修改后的结果、一个真实失败状态、窄屏、修复前后。源码/日志/摘要与截图绑定相同 run/revision。

截图用当次工具返回的图片或实际文件路径作为证据；若只有会话内图片，记录工具调用/时间/页面标题，不编造磁盘路径。正式报告引用实际可访问附件；本规格不包含不存在的产品截图。

跨源 iframe 探针成功不保证实际 E2B 的 CSP、cookie、重定向完全兼容；必须在部署的 iframe 上重测。若工具无法展开，先截图和真实坐标操作；新标签可补充定位问题，但不能把“新标签成功”当作嵌入预览已经通过。

### 3.3 控制台与响应式

可用当前 Tab 的 `dev.logs({levels:["error"],limit:...})` 读取控制台。当前会话没有核实通用网络拦截、context、route 或离线模拟 API，不在脚本中虚构它们；相关故障由测试服务断流/适配器注入实现。

视口设置先读 capability 文档，使用已提供的 viewport.set，例如桌面 1280×800 与窄屏 390×844；结束后 reset。浏览器只读 DOM evaluate 可测 `scrollWidth/clientWidth` 等渲染事实，不得用 evaluate 改应用状态、跳过登录或发请求替代用户流程。

### 3.4 等待与失败处理

以可见阶段和有界 locator 等待为主，不用固定长 sleep 判断完成。单次等待最长不超过 60 秒，随后观察状态、错误和进度并继续；总任务等待以服务端 10 分钟上限及少量网络余量为限。出现终态立即判断，不盲等满时长。

如果预期节点不在快照中，先检查页面是否进入错误/登录/加载状态；刷新观察或截图后定位，不点击猜测的旧编号。发现 blocker 停止依赖它的用例，继续独立用例；修复后复测失败步骤及受影响主流程。

## 4. 发布关键路径用例

下面所有 E 用例的当前结果都是 **NOT_RUN**。记录中的“通过”是判定标准，不是已发生的测试结果。`证据` 中的服务器查询是补证，与 UI 操作结果分别记录。

### E01 · 登录与进入项目列表 · P0

- 前置：Online Demo 或 staging，A 无登录态。
- 步骤：通过 UI 输入 A 的账号密码并登录；确认项目列表；刷新；退出；再次打开原受保护 URL。
- 通过：登录后进入自己列表，刷新正常；退出后回登录且不显示缓存项目内容。密码不出现在 URL、日志或报告截图。
- 证据：登录后/退出后页面状态；401/身份验证集成结果另见 I09。

### E02 · 错误账号、过期身份 · P0

- 前置：隔离账号；维护者可使测试 session 失效。
- 步骤：输入错误凭据；更正后登录；使身份失效；尝试读取项目和发送新需求。
- 通过：通用错误提示；正确登录可恢复；过期身份刷新失败后要求重登录，没有未经授权的新 run；未接受的草稿保留。
- 证据：可读错误与任务计数；不能仅因按钮灰掉就断言后端拒绝。

### E03 · 空项目、输入边界与中文输入 · P0

- 前置：A 登录，容量足够。
- 步骤：新建项目；查看空态；提交空格/超 8,000 字符内容；输入中文并用输入法确认候选；Shift+Enter 换行；准备合法需求。
- 通过：项目生成独立 URL；非法输入不产生 run；输入法确认不误发，换行与发送规则正确；示例按钮只填文本。
- 证据：空态/字段提示和数据库中无多余 run。不要通过 DOM 注入超长值，使用正常输入操作。

### E04 · 真实生成需求 A · P0

- 前置：新空项目，真实模型/E2B，所有 fixture 关闭。
- 步骤：输入需求 A；发送一次；观察真实阶段；打开结果；记录 run/revision；查看至少 2 个实际源文件。
- 通过：真实模型及远程工具执行；生成多文件代码，构建、保存和预览成功；结果具备报名目标，不是静态成功动画。
- 证据：需求消息、阶段与源码；模型调用/命令/快照记录。若 F13/F14 已接入，还须 E21 通过才声明团队完成。

### E05 · 预览里的真实业务行为 · P0

- 前置：E04 结果。
- 步骤：空提交；填 `not-an-email` 提交；正确添加 3 条数据；将田禾确认；按“林”搜索；刷新该应用。
- 通过：必填/邮箱错误明确；有效记录新增一次；状态变为已确认；搜索结果正确；同来源刷新后这 3 条记录保留。
- 证据：输入/提交后的 DOM 与关键截图。浏览器自动原生校验可接受，但必须真实阻止无效提交。

### E06 · 刷新、新标签、版本标识 · P0

- 前置：E04/E05 预览健康。
- 步骤：点击工作台刷新预览；点击新标签打开；通过 tab inventory 找到新增标签；比对版本与行为；返回工作台切换桌面/窄屏容器。
- 通过：都是所选 revision 对应构建；控件可用；没有意外打开旧版本。窄屏切换不重新生成应用。
- 证据：实际 URL、revision 标识、两处渲染；新标签用完关闭本次创建的标签。

### E07 · 真实源码查看 · P0

- 前置：已保存版本。
- 步骤：打开代码页签；选择入口和另一个组件文件；检查路径、内容和版本；刷新再打开。
- 通过：内容来自真实快照，能对应业务行为；只读，无虚假的保存代码按钮；依赖/环境密钥未展示。
- 证据：文件路径/hash 摘要。任意路径与他人快照访问由 I09 额外验证。

### E08 · 第一次追加修改 · P0

- 前置：E04 成功项目。
- 步骤：发送修改 1；确认仍在原项目；执行中查看旧成功预览；完成后在新版本重新录入测试数据；组合搜索和状态筛选；复测新增和错误邮箱。
- 通过：新 revision 与原项目关联；旧预览在候选生成期间不被破坏；筛选与搜索交集正确，原行为仍正常。
- 证据：修改前后 revision/sourceHash、真实操作、原行为回归记录。

### E09 · 第二次追加修改 · P0

- 前置：E08 成功。
- 步骤：发送修改 2；新版本录入 3 条并确认田禾；核对统计；切不同筛选；在 390px 应用容器操作新增/筛选。
- 通过：总数 3、已确认 1，筛选不改变统计口径；前两轮行为保留；窄屏没有整页横向溢出或不可点击控件。
- 证据：第二轮结果、统计与窄屏截图；不能以“手机图标点亮”代替窄屏行为。

### E10 · 生成中刷新工作台 · P0

- 前置：一次正常真实修改已被接受，尚在执行。
- 步骤：记下 run ID；刷新工作台；观察恢复；等待结果；检查聊天和角色活动。
- 通过：恢复同一 run；用户消息、模型任务和结果各一份；状态最终收敛，不倒退到开始，不重新 POST。
- 证据：刷新前后同一 run ID；I01/I04 对请求和事件去重补证。

### E11 · 离开、重新登录后的平台持久化 · P0

- 前置：E09 完成。
- 步骤：记录项目/revision 和两段源码 hash；退出；重新登录；从列表打开原项目；查看历史和代码；按需恢复预览。
- 通过：需求、两轮修改、结果与源码仍在；不能只恢复一个失效 URL；项目资产不是由当前浏览器缓存拼出来。
- 证据：重新登录页面与服务端快照核对。不要求另一个预览来源自动拥有之前 localStorage 的报名数据。

### E12 · 第二种需求与项目隔离 · P0

- 前置：A 的报名项目已存在；真实模型/工具开启。
- 步骤：新建读书项目，输入需求 B 并等待；添加两本书、标已读和筛选；回报名项目。
- 通过：第二套需求实际生成；界面和功能符合书单，不残留报名字段；报名项目源码/历史/当前版本未变化。
- 证据：两个 run 的实际工具/源码记录及业务操作；这是第二条真实生成样本，不使用预制 fixture 充数。

## 5. 异常与恢复用例

### E13 · 模型阶段停止 · P0

- 前置：隔离环境 `SLOW_MODEL`，或真实足够长的生成；报告区分二者。
- 步骤：开始任务，在模型执行阶段点击停止；重复点一次；刷新页面；等待清理确认。
- 通过：“正在停止”先出现；确认后“已停止”；不再调用后续角色、不产生 current 版本；同一停止请求幂等。
- 证据：UI 终态、Pi abort/信号记录；若用了 fake 慢响应，此用例不单独证明真实 provider 的中断，G0 要补一次真实流取消。

### E14 · 远程命令阶段停止 · P0

- 前置：隔离环境在真实 E2B 执行一个受控长命令，包含可观察的周期写入，不模拟远端句柄。
- 步骤：UI 开始任务；到命令阶段点击停止；等待确认；查看上一成功预览；随后尝试新任务。
- 通过：已知进程/候选 sandbox 真正结束，周期写入停止；旧预览不受影响；确认前不接受新任务，确认后可正常开始。

### E15 · 模型失败与用户重试 · P0

### E16 · 构建错误与修复 · P0/P1

### E17 · 沙箱失效后的预览恢复 · P0

## 8. 集成测试与故障注入

### 8.1 不由 UI 单独证明的不变量

建议使用 TypeScript 测试 runner、Fastify inject/HTTP、真实隔离 Postgres 和 adapter 测试。不要只 mock repository 然后宣布数据库唯一约束通过。

| ID | 精确验证 | 必须断言 |
|---|---|---|
| I01 幂等/互斥 | 并发发送同 key、不同 key、同 key 不同 body；生成与 restore 同时提交 | 同 key 同内容一个 run/用户消息；不同请求同项目至多一个 accepted；冲突没有隐藏排队；项目操作正常释放 |
| I02 远端取消 | Pi streaming abort；真实 E2B 长命令/子进程；create 尚未返回时取消 | 信号传递；进程或整个候选被确认结束；迟到创建被销毁；旧成功 sandbox 不误杀；清理失败仍阻塞 |
| I03 停止/完成竞争 | 在 finalize 事务前后并发 cancel；延迟 tool result | 取消先提交则无 promote；完成先提交则终态保持 completed；迟到结果不派下个角色 |
| I04 SSE | 历史读取和实时订阅之间插入事件；重复/分块/断流/慢客户端；token 过期 | cursor 单调、无漏关键事件、UI 去重；过期后重鉴权；客户端离开不取消 run；普通 subscriber 不冒充 await 屏障 |
| I05 snapshot 事务 | 上传失败；上传成功 DB 提交失败；超限/链接/路径逃逸；恢复 roundtrip | current 不悬空；孤儿对象可识别；未引用对象不当成功版本；恢复 hash 一致；不吞二进制或密钥文件 |
| I06 版本绑定 | 错 revision/hash/attempt/session 的报告；检查期间源码变化 | 拒绝结果且不 promote；所有附件和事件归属相同版本；修复不复用旧 browser session |
| I07 重启恢复 | 持久化 accepted 后未启动就停进程；build 中退出；重启扫描 | 遗留任务 interrupted，保留原请求/current；不透明重放 shell；清理确认前不接受新任务 |
| I08 角色/预算 | Coordinator/Reviewer 调写工具；重复 handoff；持续失败；schema 无效；needs_input | 服务拒绝写入；每 role/attempt 唯一；repair≤2；预算停机；澄清释放槽；不会仅根据头像或模型“完成”改变状态 |
| I09 owner/路径 | B 访问 A 的项目/run/SSE/source/artifact/cancel/retry/restore；任意路径和 URL | 所有被拒绝；无数据/状态副作用；可信服务凭据不出现在响应、日志、bundle 或 E2B env |
| I10 浏览器 adapter | refs 失效、导航越界、命令参数注入、输出路径、超时、close | 仅允许受控动作/来源，拒绝跨 session refs；JSON/截图正确处理；观察重试不盲重放写动作 |
| I11 生产部署 | 构建产物、单实例配置、proxy/SSE、故障开关、schema/bucket 权限 | 正常前端资源齐全；API/SSE 可用；生产禁止 TEST_PROFILE；anon 不能直接读私有数据；无宿主执行生成代码 |

I01–I11 当前均 NOT_RUN。测试名只是实现建议，不代表已经有测试文件。只为上述真实风险编写必要断言，不为每个文案写镜像实现的测试。

### 8.2 故障 profile 设计

故障在测试启动配置/维护脚本中注册，绑定 test owner、scenario ID、指定次数和到期时间。UI 输入只负责触发正常请求，不能用“在 prompt 中写某口令”开启故障。生产构建或启动拒绝测试 profile；报告包含启用范围和关闭记录。

| Profile | 替换/影响边界 | 用例 | 不得据此声称 |
|---|---|---|---|
| `SLOW_MODEL` | 模型 adapter 的受控慢响应，尊重 abort | E13 | 真实 provider 已中断，除非另有真实测试 |
| `LONG_REMOTE_COMMAND` | 在真实 E2B 添加测试长命令 | E14 | 仅 UI 停止即证明进程退出 |
| `MODEL_ERROR_ONCE` | 首次模型调用抛不可重试测试错误 | E15 | 初次任务调用过真实模型 |
| `INVALID_TS_FIRST_ATTEMPT` | 首次 Builder 产物夹具，后续 Builder 真实 | E16 | 初次代码由真实模型生成 |
| `BROKEN_FILTER_FIRST_ATTEMPT` | 构建正常但筛选失效的首版夹具；后续修复真实 | E22 | 所有自然生成任务必然出现相同缺陷 |
| `PERSISTENT_BROKEN_FILTER` | 所有 Builder attempt 保留已知缺陷 | E23 | 自动修复质量差或好；此例只验证上限 |
| `PREVIEW_UNREACHABLE` | 指定候选的预览访问失败 | E24 | 产品已检查业务逻辑 |
| `STORAGE_WRITE_FAIL` | 指定 snapshot 上传失败 | E27 | Supabase 实际发生过事故 |
| `SSE_CLOSE_ONCE` | 只关闭目标事件连接 | E20 | 模型/远端任务停止 |
| `SHORT_DEADLINE_CLEANUP_DELAY` | 缩短测试预算、延迟一次清理确认 | E30 | 生产超时阈值与测试相同 |

若 profile 不存在，先实现最小必要夹具或记 BLOCKED；不能手改数据库为通过状态来补成绩。真实 E04/E08/E09/E12 的结果不得与这些 fixture 运行混成一个成功率。

### 8.3 数据清理

维护脚本按本轮 test prefix/run manifest 精确找出自己创建的资源，先取消活动任务并确认，再销毁测试 sandbox、删除指定测试数据/附件。不要按全库 truncate、任意项目名或删除整个 bucket 清理。正常账号没有产品删除功能不妨碍维护环境做精确 reset；这是测试设施，不属于 PRD 新增功能。

保留发布候选的实际成功/失败记录、关键截图、配置版本和源码 hash；只清除无用测试数据。清理失败单独记录，不把仍在消耗额度的资源当成已释放。

**开发 smoke**：E01/E03/E04/E05/E07，接着 E08/E09/E10/E11；早期每修一次主链路就复测相关部分，不为无关文案改动重新消耗两套完整生成。

**发布候选完整验收**：E01–E30、I01–I11、D01–D05 中与当前交付阶段适用的项目；真实生成至少 A 的初次+两次修改和 B 的初次。故障用例在隔离环境执行，线上重跑 E01/E04/E05/E08/E11/E21 与 D01。其它正常 UI 行为可复用同一测试项目降低调用成本。

严重度：S0 为数据/凭据泄漏、跨用户越权或不可控资源；S1 为主流程不可用、假成功、取消无效、资产丢失；S2 为重要非阻塞交互问题；S3 为外观细节。所有 S0/S1 必须修复并复测才能宣称对应交付可用；保留的 S2/S3 要在说明中列出影响。

F13/F14 是本轮选定 P1；若 E21–E24 或相关 I 用例未通过，只能交付“核心流程已完成、团队延展未完成/部分完成”的真实状态。不能因原题延展是条件性目标，就把自己已承诺的 P1 默默标为完成。

PASS = 实际结果满足全部断言；FAIL = 已执行且不满足；BLOCKED = 前置条件或工具缺失；NOT_RUN = 尚未执行；N/A 必须解释需求为何不适用。BLOCKED 和 NOT_RUN 都不算通过。
