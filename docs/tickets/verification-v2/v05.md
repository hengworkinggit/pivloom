## What to build

验证器用稳定测试资产与可解释状态处理应用错误、测试错误和基础设施错误，避免无变化反复整轮生成。

## Acceptance criteria

- [ ] 结果区分app assertion、test/setup、infrastructure、timeout、not-run；测试坏或工具坏不会盲目触发Builder修应用。
- [ ] 同一候选同一测试无变化重复执行受控；修复以失败项及必要回归为范围，完整required发布账目仍保留。
- [ ] 工作台/接口显示实际覆盖与耗时；旧证据不冒充当前，检查受阻不清空已完成结果。
- [ ] 代表性好/坏应用样本校准假通过、假失败、取消与恢复；至少覆盖计算器、表单列表、动态UI与Canvas相关能力。
- [ ] 同一模型/环境的真实增量计时包含全部验收阶段；10分钟内可靠完成是实测条件，超时或blocked不算达标。
