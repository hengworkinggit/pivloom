# Pivloom 技术复核：上游复用、五组验收、Canvas 与版本回滚

## Problem Statement

评审者需要从空项目复现两种不同应用的真实生成，在同一项目验证功能与视觉增量，并在新会话、退出重登、跨账号和版本回滚后看到一致的项目、对话、源码、版本及 Preview。旧报名/书单样本、构建成功和有限的 5/5 显示，不能证明本次要求已满足。

当前实现存在会影响复核的缺口：旧必需行为可能从增量计划丢失；截图未真正进入 Reviewer 模型；浏览器包装未完整暴露四向按键与等待；Builder 取消存在被写成失败的分支；终态持久化和资源清理存在失败窗口；平台没有已验收版本回滚及可核对的部署 SHA。

## Solution

沿用现有工作台、Pi、OpenSandbox 与 Supabase，直接采用已核查的官方 SDK/CLI 能力和开源局部实现，完成可复现的真实生成、检查、修改、恢复与回滚路径。用户看到固定五个验收组及完整子检查；只有组内全部必需项通过才算这一组通过。

本轮正常样本为全新计算器、同项目功能和视觉两轮增量，以及另一个全新 Canvas 贪吃蛇。每个模块完成立即执行关联 E2E，最后冻结实际 Web/API 产物再做整链复核。

## User Stories

1. 作为体验者，我希望从空项目用自然语言生成计算器，以便验证真实模型实现了需求。
2. 作为体验者，我希望在另一个空项目生成 Canvas 贪吃蛇，以便确认平台能处理不同应用而非固定业务模板。
3. 作为用户，我希望模型和工具的实际执行可见，以便区分真实生成与演示数据。
4. 作为用户，我希望在同一项目追加功能，以便保留已有作品并继续迭代。
5. 作为用户，我希望单独修改视觉和窄屏布局，以便改善界面而不丢失已有功能。
6. 作为用户，我希望所有旧必需行为持续接受检查，以便新增功能不掩盖回归。
7. 作为评审者，我希望看到固定五个验收组及完整子项，以便知道 5/5 的实际覆盖范围。
8. 作为评审者，我希望未执行、受阻或失败的子项不能计入通过，以便检查结论可信。
9. 作为用户，我希望 Reviewer 真正读取浏览器截图，以便发现 Canvas、布局和交互状态问题。
10. 作为用户，我希望模型不支持图片时得到明确提示，以便选择可用配置而不遭遇静默丢图。
11. 作为用户，我希望浏览器能执行正常方向键、空格和短动作序列，以便检查动态小游戏。
12. 作为用户，我希望游戏的计分、碰撞、暂停和重开经过真实操作，以便生成结果实际可玩。
13. 作为用户，我希望任一角色执行时都可以停止任务，以便终止模型和远端工作。
14. 作为用户，我希望停止、超时、服务中断和普通失败分别显示，以便采取正确的后续动作。
15. 作为用户，我希望清理尚未确认时看到真实状态，以便不会误以为资源已经释放。
16. 作为用户，我希望短暂数据库或销毁故障恢复后任务能收口，以便项目不永久停在执行中。
17. 作为用户，我希望重试创建可追溯的新 Run，以便旧失败记录保留且不会重复副作用。
18. 作为用户，我希望刷新或网络断开后恢复同一 Run，以便不会因重连重复提交需求。
19. 作为用户，我希望从新浏览器登录后仍能读取项目、对话、源码和版本，以便跨会话继续使用。
20. 作为用户，我希望退出后旧私有预览凭证失效，以便切换账号时不继承前一个账号的访问权。
21. 作为用户，我希望另一个有效设备会话仍可使用，以便本地退出不会误伤自己的其他会话。
22. 作为用户，我希望查看全部历史版本和完整源码差异，以便理解每轮实际改动。
23. 作为用户，我希望浏览旧版本时不会悄悄改变 current，以便查看与回滚的含义清楚。
24. 作为用户，我希望回滚到已验收版本，以便源码、Preview、版本号和当前对话基线一致。
25. 作为用户，我希望回滚失败保留原 current，并且重复请求不会重复执行，以便恢复过程可靠。
26. 作为用户，我希望回滚保留后续历史，以便仍能追溯过去的修改。
27. 作为用户，我希望回滚后的下一轮修改从目标旧版本开始，以便旧上下文不会意外带回。
28. 作为用户，我希望临时预览恢复与永久发布继续分开，以便只在主动发布时更新公共站点。
29. 作为评审者，我希望页面展示真实 Web/API 部署 SHA，以便把证据与实际运行产物对应起来。
30. 作为维护者，我希望复用固定版本且许可明确的上游实现，以便减少重复开发和升级漂移。
31. 作为维护者，我希望每个模块完成后立即有关联 E2E 结果，以便在最后整链之前发现问题。
32. 作为项目所有者，我希望评审账号、既有作品及已关闭的定时任务状态受到保护，以便复核不破坏当前交付环境。

## Implementation Decisions

- **运行底座**：保持常驻 Fastify 和进程内 Pi SDK；三个 Pi 包固定 0.86.1，采用官方会话、工具 operations、重试、ImageContent 和 compaction。0.87.x 的停止钩子/上下文变更作为独立升级，不混入本轮。
- **必要预重构**：把重复的角色装配、信号桥接和事件转存收敛为薄宿主，逐角色迁移并保持回归可运行；不引入第二套 Agent loop 或通用工作流框架。
- **取消和结束**：等待 Pi abort、idle/settled 与当前运行收口；取消原因贯穿模型和工具。Builder 的 cancelled 必须进入取消终态。借鉴 OpenHands 的先置取消、再中止及迟到工具仍能看到取消的顺序。
- **持久化责任**：PostgreSQL 是 Run、Revision、Check 和项目 current 的事实来源。Pi 的事件订阅不会等待外部异步写库，保留事件 drain。终态落库失败不能被吞掉后丢弃任务责任；幂等收口和清理对账不重新调用模型。
- **重试与限制**：Provider 重试只由一层控制，优先 Pi 原生策略；成功响应重置连续错误计数。用户显式重试产生关联的新 Run。继续不设累计 Token 停止上限，时间、工具、资源和供应商边界分别记录与验证。
- **五组与子项**：新验收契约使用五个稳定 group，引用完整原子行为 ID；每个 required 子项完整且唯一归组，服务端从子项证据聚合状态。增量保留所有旧 required，明确需求变更才允许记录替代。历史平铺 Check 按旧格式读取，不倒填更强覆盖。
- **真实图像**：截图元信息和实际图片共同返回 Pi，保留 MIME、顺序与 revision/observation 绑定。实际选定并冻结的 Provider 必须通过视觉探针；未知或不支持时阻塞视觉通过并明确提示，不静默切换模型、丢图或降为 DOM 棋盘。
- **浏览器操作**：固定 agent-browser 0.38.1，直接使用原生 press、wait、batch、screenshot。借 OpenManus 图像反馈及历史小游戏 recipe 的短动作后重新观察方式；不复制浮动 Python 浏览器运行时。游戏状态只能由真实输入改变。
- **私有预览**：沿用 Supabase local sign-out，关联已验证身份的 session_id，并核对服务端 session 有效性。预览凭证只授权对应私有资源，不授予普通 API 权限；退出当前会话后拒绝旧凭证的新请求，其他有效会话仍可用。
- **历史与差异**：提供 owner 隔离的历史版本与完整文件差异，区分 accepted、candidate 和 rejected。只读选择不改变 current 或下一轮基线；差异包含新增、删除、移动和内容变化。
- **原子回滚**：采用 Dyad 开放实现的准备、互斥、应用、提交与检查点恢复次序，接现有不可变源码快照。回滚请求包含目标版本、预期 current 与幂等键；先准备干净目标 Preview，确认源码和 marker 后再事务切换 current、记录对话回滚事件。
- **回滚语义**：第三版切回第一版，版本号真实显示第一版，后续历史保留；下一次生成使用新的递增编号并继承目标源码/计划。回滚本身不调用模型，不自动重新发布公共站点，也不承诺回滚生成应用的 localStorage。
- **故障恢复**：回滚准备、提交和响应丢失窗口都有持久化操作记录；取消/成功竞争由合法数据库转移决定唯一结果。远端 kill 与客户端 close 区分，确认资源已销毁后才解除相应占用。
- **部署来源**：从确定提交干净构建，把同一次构建输入写入 Web/API 产物；页面可复制各自 SHA，并可与接口和 manifest 核对。重启同一包不改变 SHA，不用运行时 checkout HEAD、bootId 或应用 sourceHash 冒充。
- **许可与复制边界**：按已固定的复用清单复制或调用，保留版权、LICENSE/NOTICE 和适配说明。Dyad 限制许可目录、未公开 Manus Agent、OpenManus 多模态硬编码名单及第二套 Git 状态引擎不进入本轮。
- **环境保护**：生产已只保留 A；A/B 隔离使用同构隔离环境和临时合成身份，精确清理，不恢复旧 B 或清理 A 正式作品。Codex 巡检与飞书评论自动化保持停用。

## Testing Decisions

- 最高用户入口为独立真实浏览器，从 UI 登录、创建项目、发 Prompt、操作应用、查看源码、停止/重试和回滚；产品 Reviewer 与 QA 使用不同浏览器会话。
- 后端补证优先使用现有 API、PostgreSQL repository、Workspace/Browser adapter 边界，验证可观察状态与副作用，不为每个内部函数或文案建立镜像测试，不增加生产测试后门。
- 上游原样测试和离线探针只证明接口兼容；真实 Provider、OpenSandbox、视觉能力和用户应用分别执行。固定版本、模型配置和测试数据来源记录在每份报告中。
- 正常模型样本必须是计算器首次生成、同项目功能增量、同项目视觉增量和另一个全新 Canvas 贪吃蛇；所有测试产物适配器关闭。四次用户提交不能由修复 attempt 或旧报名/书单替代。
- 每轮保存项目、Run、基线/结果 Revision、revisionNo、sourceHash、完整源码差异、Check、Preview marker、模型配置版本及 Web/API SHA。五组通过及子项明细与实际证据对应。
- 新浏览器、退出重登、同浏览器切 B、独立 B 与另一有效 A 会话分别验证项目、对话、源码、历史版本和私有 Preview。公开发布地址匿名可读是预期行为。
- 回滚核对完整文件集合，不只比对主文件/hash；覆盖重复请求、越权、未验收目标、准备失败、响应丢失、并发与进程重启。用下一轮修改证明基线已切换。
- 生命周期故障按明确阶段 gate 触发：模型/命令取消、退避/压缩取消、终态事务失败、销毁首次失败、SSE 断线、超时及服务重启。fixture 在隔离环境执行，与真实模型记录分开。
- 沿用 Pi 官方 retry/settled/image/compaction 测试、Dyad 终态/回滚测试、OpenHands interrupt/Cookie scope 测试、OpenCode 完整文件/快照竞态测试作为断言来源；只移植适合本产品语义的部分。
- 每个子 issue 完成后立即执行其 E/I 用例与相关 UI 回归；实际通过、失败修复复测后才关闭。FAIL、BLOCKED、NOT_RUN 不能算通过，最终整链不能替代模块即时验收。
- 最终冻结明确的 Web/API 产物，复核全部必需 E01–E42、I01–I21；I22 仅显式升级 Pi 才适用。游戏额外两轮增量是可选扩展，不能替代必需的计算器两轮。

## Out of Scope

更换 Pi 为 OpenManus/OpenHands 全运行时、叠加 LangGraph/Deep Agents、复制限制许可或未公开代码、多实例任务平台、生成应用通用后端/云数据库、业务数据跨 origin 迁移、自动永久发布、团队/支付/邮箱变更、恢复小时巡检或自动评论回复。真实生成、回滚、视觉与隔离要求不因这些边界而缩减。
