# 已发布应用的数据边界

源码版本、Preview 示例数据和线上业务记录是三种不同资源。

- Preview 的活动报名和预约记录只存在该浏览器中；更换浏览器或源码版本不会自动迁移示例数据。
- 发布后的报名和预约由同域 `__pivloom/data` 接口写入 PostgreSQL，记录按 `owner_id + project_id` 隔离。它们不属于沙箱，也不随源码版本切换或回滚而删除。
- 公开访客只能提交报名、预约以及读取不含身份信息的已占用时段。项目主人通过已认证的工作台接口查看、确认、删除和导出记录。
- 服务端验证字段、限制每项目 10,000 条和每小时 1,000 次提交；数据库唯一约束防止重复报名及同一日期时段的并发重复预约。浏览器不持有数据库密钥。
- 发布资格和回滚资格由同一个 `nano.revision_eligible` 规则判断。托管数据项目额外要求当前源码具有有效的 `pivloom.data.json` 和运行时数据模块；旧的本地版模板需要重新创建或增量升级后才能作为在线报名、预约应用发布。
- 发布复制的是静态代码。线上业务数据从不复制回 Preview，Preview 示例数据也不会在发布时进入线上。发布时的代码版本和生产数据生命周期独立。

当前托管数据覆盖活动报名和预约排期。个人读书清单、任务看板仍为浏览器本地工具；给它们增加跨设备数据之前，需要确定应用用户身份与“每人独立”或“多人共享”的权限模式。这个版本也未提供通用的动态数据模式、文件上传、自动通知或离机备份。数据已具备跨服务重启和代码版本切换的持久性，但不能据此承诺服务器损坏时零数据丢失；正式对外承诺恢复能力前必须配置备份和恢复演练。

验收时至少覆盖：两个浏览器提交后主人都能看到；公开接口不能列出联系人；两个并发请求争夺同一时段只有一个成功；重复请求标识只创建一条记录；重启 API、发布新代码和回滚源码后记录仍在；模拟数据接口故障时发布页阻止提交而不是回退到本地存储。
