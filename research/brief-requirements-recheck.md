# 原题要求、Atoms 功能与本次交付：逐项复核

核验日期：2026-09-21。通过 lark-cli 重新读取[飞书原题](https://deepwisdom.feishu.cn/wiki/EHf8wgbtbibv8JkOkjNcXTD4nlg)，revision 510；重新打开 Atoms 官网和当前帮助中心。本文供本地规划，不复制私人题面全文及联系人信息。对外 README 只写我们的实现与使用说明。

后续范围细化：用户确认参考 Multica 后，P1 浏览器检查扩展为固定三角色的真实交接流程，见[团队机制](multica-team-reference.md)。原题要求的解释不变；完整多团队管理仍延期。

## 1. 核心纠正

任务是交付一个可运行、可体验、可扩展的 **Atoms Demo**。原题没有要求复制完整 Atoms 功能清单。此前“完整对齐”来自用户后续扩大目标，现在以用户明确的时间限制收敛。

**48 小时从收到任务起计算，是提交期限；6–8 小时是建议的集中开发时段。** 不能理解成 48 人时，也不能每次改计划都重新计时。目前没有确认收题时间，不编造准确截止时间。

## 2. 题面要求与完成定义

“明确要求”来自原题；完成定义是我们选择的实现，不意味着题目指定这些技术和流程。

| 编号 | 题面要点 | 约束强度 | 我们如何证明 |
|---|---|---|---|
| R01 | Agent 驱动代码或应用生成 | 明确要求 | 在线输入新需求，真实调用模型和工具，产生能运行的代码 |
| R02 | 生成结果可视化展示，具备类似 Atoms 的能力和 UI 交互体验 | 明确要求，没有逐菜单清单 | 项目工作台、聊天、执行状态、应用预览；具体布局由我们设计 |
| R03 | 真实交互 | 明确要求 | 聊天产生实际修改；预览内的导航、表单或按钮真实工作 |
| R04 | 数据持久化，技术不限 | 明确要求，未指定数据层 | 保存项目、会话、源码和结果版本，重新打开后可继续使用 |
| R05 | 在线可测试 Demo，功能实际可用 | 明确要求 | 评审能访问部署后的工作台并走通流程，不依赖开发者本机 |
| R06 | GitHub 源码与笔试文档 | 明确交付项 | 提供链接、运行方法和环境变量说明；按题面 public 要求核对提交材料访问权限 |
| R07 | 收题后 48 小时内提交 | 明确期限 | 按实际截止时间倒排，并留出交付检查时间 |
| R08 | 集中开发 6–8 小时 | 建议 | 体现对原型复杂度的预期，不是全功能复制的工期承诺 |
| R09 | 初始化、注册、核心流程等 | 时间资源允许时尽量覆盖；注册是示例 | 保留创建项目与主流程；自助注册可延期，评审入口必须可用 |
| R10 | 至少一个延展或衍生能力 | 与 R09 同属条件性目标 | 主动选择一个做实，不误写成无条件题面硬门槛 |
| R11 | 思路、取舍、完成程度、后续优先级说明 | 强烈建议 | 提供简短交付说明，明确哪些做了、哪些没做 |
| R12 | 个人文档副本、署名与提交回收流程 | 明确提交步骤 | 提交时处理副本与权限；本次不替用户发送消息或提交 |

### 三个容易误读的边界

**持久化**：题目未明确要求为每个生成应用提供数据库。服务端保存项目、聊天、源码和结果，是合理、可验证的落实方式；这是我们的解释，不保证评审没有其他期待。我们选择服务端持久化，以便刷新、重新登录、沙箱重建后继续使用。生成应用的业务数据库、认证、上传和 Cloud 管理台属于另外的能力。

**部署**：明确要求上线的是我们做的 Atoms Demo 工作台。每个生成应用都一键发布到独立永久域名，是 Atoms 的功能，但不是题面明示要求。预览必须真实可用，沙箱失效后应从保存源码重建，不能只保存过期 URL。

**GitHub**：交付本项目的源码仓库是要求；产品内开发 OAuth、建库、Push/Pull 连接器是额外功能。两者不能混淆。

## 4. Atoms 真实功能与本次覆盖

事实来自官方公开文档，**没有登录做端到端实测**。原题旧文档站本次访问失败，当前官网 Help Center 指向 help.atoms.dev。产品有此功能，与笔试必须实现，是两个判断。

| 功能 | 官方确认的体验 | 本次取舍 |
|---|---|---|
| 对话开发与持续修改 | 同一项目追加需求，显示活动和工具操作，产生版本；有排队、停止及错误修复入口。[Project Chat](https://help.atoms.dev/en/articles/12129550-project-chat) | 保留聊天、状态、停止、串行追加修改；不做完整排队管理 UI |
| 需求输入 | 支持文字、附件和可用模式入口。[Input Chat](https://help.atoms.dev/en/articles/12129552-input-chat) | 文字必做；附件和多模式延期 |
| 单工程师与团队 | Team Mode 关闭时由 Alex 处理；开启后 Mike 协调专家，有问题、计划和版本卡。[Working with Agents](https://help.atoms.dev/en/articles/12129548-working-with-agents) | P0 先做单工程师闭环；P1 固定三角色真实协作，显示实际步骤与交接 |
| 交互预览与修复 | 可点击、输入、提交表单；有视口、刷新、页面选择、打开新标签和日志；Resolve 尝试修复问题。[App Viewer](https://help.atoms.dev/en/articles/12129554-app-viewer) | 保留可操作预览和错误状态；由 P1 的独立检查者执行浏览器操作，并反馈工程师修复 |
| 源码与文件 | 查看和编辑源码，提交或放弃修改。[Code and files](https://help.atoms.dev/en/articles/12129559-code-and-files) | 做轻量只读源码视图；手动编辑与可写终端延期 |
| 视觉编辑 | 点选元素、描述局部改动或调样式，受项目状态和权限限制。[Design](https://help.atoms.dev/en/articles/12129553-design-and-preview) | 属于 Atoms 核心编辑体验；本次明确未对齐，不做完整 Visual Editor |
| 历史与恢复 | 查看版本、Restore 当前项目、Remix 新项目；数据库选项另行处理。[History](https://help.atoms.dev/en/articles/12129557-project-history) | 必须保存结果快照；恢复 UI 有余量再做；不做 Remix/数据库回退 |
| Cloud 后端 | AI、数据库、用户、密钥和存储构成生成应用后端。[Atoms Cloud](https://help.atoms.dev/en/articles/12129561-atoms-cloud) | Supabase 先用于平台数据，不能据此声称已复制 Cloud |
| 发布与更新 | Publish 生成外部站点 URL，后续修改需要 Update 才上线，区别于项目分享。[Publish](https://help.atoms.dev/en/articles/12129577-publish-your-project) | Demo 工作台必须上线；生成应用一键独立部署延期 |
| 分享与代码交付 | 项目分享、源码 ZIP 与 GitHub 连接是不同能力。[Share](https://help.atoms.dev/en/articles/12129574-share-a-project)、[GitHub](https://help.atoms.dev/en/articles/12129569-connect-github) | 交付本项目仓库；生成代码 ZIP 可选；同步连接器不做 |
| 多种输出 | Web、App、Video 等有不同创建入口和工作流。[Output types](https://help.atoms.dev/en/articles/12129547-output-types) | 本次只做 Web；原生移动和视频没有题面逐项要求 |
| 平台其他能力 | Research、Race、连接器、SEO、Ads、套餐额度等。[官网](https://atoms.dev/)、[Integrations](https://help.atoms.dev/en/articles/12129568-integrations)、[SEO](https://help.atoms.dev/en/articles/12129581-seo-agent)、[Ads](https://help.atoms.dev/en/articles/12129582-ads-agent) | 本次全部延期，属于完整产品功能而非自动成为笔试要求 |

对齐重点是同一项目里的连续开发体验。视觉编辑、历史和发布确实是 Atoms 的能力，本次延期必须写清楚；不能为了减范围就否认这些功能，也不能由“参考 Atoms”推导成整个平台都必须复制。

## 5. 修正上一版范围

- **移出必做**：生成应用独立数据库及双环境、一键部署生成应用、自助注册、源码 ZIP、版本恢复 UI。上一版把自己的设计选择升格成了过多的必做任务。
- **保留多文件工程**：这是我们为持续修改选择的实现，非题面指定；已有 Pi/E2B 研究支持，无需重新换底座。
- **加强工作台体验**：源码视图、真实步骤与状态、失败重试、刷新后继续开发。只读源码从可选升为我们的体验目标。
- **延展只选一个**：固定三角色协作与浏览器检查。协调者分派、工程师实现、独立检查者执行导航或表单任务，失败交回有限修复。它不是市场首创，也不承诺通用多团队或全自动验收。
- **M3/M4 仍移出**；M2 视觉编辑、完整历史/Remix、Cloud 和运营后台明确记为未实现。
- **优先级**：核心流程与持久化 → 尽早上线可测试 Demo → 团队协作与浏览器延展 → 体验与说明。生成应用独立发布不能挤占工作台自身上线。

## 6. 我们制定的验收清单

1. A01：评审可从线上地址进入并操作，无需开发者本机配合。
2. A02：新需求触发真实模型与工具调用，生成并运行代码；更换需求后有对应结果，非预置页面切换。
3. A03：预览中导航、筛选或表单有实际行为。
4. A04：追加修改更新原项目，主要已有行为仍可用。
5. A05：重新进入能找回消息、源码和结果；失效预览可恢复运行。
6. A06：停止有效，模型/构建失败可理解并可重试，不显示假成功。
7. A07：可查看真实源码，活动展示与实际工具一致。
8. A08：三个角色各自执行实际任务，检查者操作浏览器；发现问题时交回工程师修改，再检查对应版本。另用可复现故障用例验证修复分支，不要求每个生成结果都出现缺陷。显示简短结果，详细证据用于调试。
9. A09：在线与 GitHub 链接、运行说明、完成/未完成列表齐全；提交前按题面 public 要求核对笔试副本和成果链接权限。公开仓库只含自己的源码与实现说明，不收录私人题面。

A01–A05/A09 主要落实题面；A06–A07 是我们的质量标准；A08 是选定延展。这是我们制定的验收方法，不冒充官方测试用例。

当前仍是研究与规划，未实现或部署产品，未创建文档副本、修改分享权限或发送提交消息。开发以[修订后的限时方案](delivery-48h.md)为准，完整功能事实参考[Atoms 核验](atoms-feature-audit.md)。
