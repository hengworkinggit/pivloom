# Reviewer 设计复核：开源实现与 Pivloom 的取舍

2026-09-24。只依据所列项目的固定提交源码；“借鉴”指移植决策结构，不能把 Python 实现直接塞进 Pivloom 的 Pi/TypeScript 运行时。

## 结论

Pivloom 的独立 Reviewer 和版本、真实浏览器证据门槛有价值，不宜删除；目前更大的问题是**把模型填报协议、产品缺陷、浏览器/基础设施障碍放在同一条高成本验收链**。Reviewer 只读取 DOM/文本，截图仅保存为工件，却可能承担视觉验收；一次检查需要覆盖所有计划行为、逐项绑定事件 ID，在模型交错工具调用时易因填报错误耗尽唯一纠正机会。这种失败不说明作品坏了。[Pivloom Reviewer 规则](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/runtime/reviewer.ts#L198-L265)、[提交逻辑](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/runtime/reviewer.ts#L458-L466)。

必须准确区分现状：`blocked` **不会**进入 Builder 自动修复。`finishReview` 只有 `failed && attempt < 2` 才生成 `repairNextAttempt`；`blocked` 最终将 Run 置 `failed` 并保留候选记录，用户可重试。问题是一次暂时性的 Reviewer/浏览器障碍会让整次生成终止，而不是先对同一候选重试检查。[数据库决策](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/data/generation.ts#L701-L733)。

## 建议落地顺序

1. **结果分类与路由**：保留 `passed/failed/blocked` 的对外 Check，内部再标注 `product_defect`、`reviewer_protocol`、`browser_infra`、`provider`、`version_mismatch`。只有来自可复现浏览器行为/运行错误的 `product_defect` 让 Builder 修复；`reviewer_protocol` 与可恢复的 `browser_infra` 在同一不可变候选上有界重试 Reviewer。当前 `blocked` 直接终止 Run 的路径见 [finishReview](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/data/generation.ts#L701-L733)。
2. **把填报机械工作交给服务端**：版本/行为清单、`expected`、事件归属和截图 ID 由服务端按工具调用组装；模型只给 `verdict/actual/reproSteps`。目前模型需准确区分 observation event ID、下一步浏览器 observation ID 和 screenshot artifact ID，且一次报告错误只能纠正一次，属不必要的格式脆弱点。[现状](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/runtime/reviewer.ts#L198-L265)。
3. **先完成视觉输入，再宣称视觉验收**：当前提示明确模型是 DOM-only，截图只是保存工件，[不能称其真的“看过图”](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/runtime/reviewer.ts#L262-L266)。图像模型接收截图并引用同一 revision 后，才判布局、颜色、遮挡；当前 DOM/视口数值仍可验证可访问性与横向溢出。
4. **验收场景分层**：可信构建、源码 hash、Preview marker、账号隔离是硬门槛；行为验收按真实 Prompt 定义最小动作，静态内容可用渲染观察+截图，交互则必须执行交互；临时不可观察记 `blocked`，观察到错误才记 `failed`。回归另用固定五组测试表达，不强迫每个生成作品都有五个业务行为。

这份研究是设计依据，未修改产品代码，也未对上游项目的 Reviewer 运行效果做实验性性能背书。

## Pi 0.86.1 本身给 Reviewer 什么

Pivloom 锁定 `@earendil-works/pi-*` **0.86.1**。固定源码提交为 [`13cbf77`](https://github.com/earendil-works/pi/tree/13cbf77df2396303013a41646bcfa77b4271ae56)。Pi 确实附带一个 [reviewer 角色示例](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/examples/extensions/subagent/agents/reviewer.md#L1-L35)，但它只读 `git diff`/文件、报告代码质量安全问题；[示例链](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/examples/extensions/subagent/prompts/implement-and-review.md#L1-L10) 是 worker→reviewer→worker。它不是 Pi 内置的浏览器验收器，也不定义产品 `passed/failed/blocked`、版本绑定或证据 taxonomy。[示例说明](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/examples/extensions/subagent/README.md#L1-L29) 明确这是扩展范例，而非 coding-agent 核心的内建多代理业务流程。

Pi 提供可直接用的 Reviewer **运行底座**：[`createAgentSession`](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/sdk.ts#L68-L78) 注入 `customTools` 和工具名 allowlist；`ToolDefinition` 的 [`prepareArguments`](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/tools/tool-definition-wrapper.ts#L4-L19) 可在[参数校验前](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/agent/src/agent-loop.ts#L648-L680)做确定性补全；Agent 循环在工具结果落入上下文后才检查 [`shouldStopAfterTurn`](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/agent/src/agent-loop.ts#L227-L260)。因此 Pivloom 可让服务端补 `revisionId/sourceHash/expected` 等封闭字段，减少模型抄写与 ID 混淆，但 Pi 不会自动判断某个浏览器观察是否证明了需求。

Pi 的 [`ToolResultMessage`](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/ai/src/types.ts#L539-L544) 支持 `ImageContent`，[官方 screenshot 工具测试](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/test/suite/agent-session-tool-result-images.test.ts#L13-L24) 返回 PNG base64；会话在[工具结果回传时归一化图片](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/agent-session.ts#L529-L548)。**直接复用这条路径即可让截图进入模型上下文**，同时仍需核对实际模型的 `input` 含 `image`，且未开启 `blockImages`；这两道条件分别见 [Model 类型](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/ai/src/types.ts#L959-L971) 与 [SDK 图片过滤](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/sdk.ts#L269-L285)。Pivloom 当前 [`browser_screenshot` 只回传 artifactId/哈希](https://github.com/hengworkinggit/pivloom/blob/4ada0e1c8361134d6928e13033907bbdbaab59a6/apps/api/src/runtime/reviewer.ts#L379-L385)，因此不能宣称模型看了截图。

其余已有能力也应各司其职：[`abort()` 等待 idle](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/agent-session.ts#L1756-L1775)，[compaction](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/docs/compaction.md#L25-L47)压缩长会话且不在工具调用/结果之间截断，[瞬态 Provider retry](https://github.com/earendil-works/pi/blob/13cbf77df2396303013a41646bcfa77b4271ae56/packages/coding-agent/src/core/agent-session.ts#L3040-L3085)有可取消的退避。这些都不等于远程沙箱销毁确认或业务验收重试。Reviewer 的证据归属、错误路由、不可变版本和发布门槛仍由 Pivloom 实现。
