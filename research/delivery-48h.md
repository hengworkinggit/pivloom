# nano-Atoms：按原题校准的限时交付方案

版本：2026-09-21 / v3。已重读飞书原题 revision 510，并复核 Atoms 核心流程，依据见[要求与产品功能复核](brief-requirements-recheck.md)。本版根据用户确认的 Multica 参考，将 P1 收敛为固定三角色协作与浏览器检查，详见[团队机制决策](multica-team-reference.md)。生成应用后端、双环境和独立发布仍不列为必做。

**时间边界：收题后 48 小时内提交，建议集中开发 6–8 小时。** 用户只有 48 小时，不再长期完整对齐。目前不知道准确收题时刻，不能把剩余期限重新当成完整 48 小时开发预算。

## 1. 产品目标

交付在线 AI Web 应用构建工作台：输入需求 → Agent 生成真实代码 → 可交互预览 → 同项目继续修改 → 保存并重新打开。提供清楚执行状态和真实源码视图。

P0 先打通真实生成链路；P1 在同一 Pi 框架内增加协调者、工程师、检查者三个独立 session，串行交接，只有工程师写源码。它是一个固定小队，不引入完整多团队管理。原 M3/M4 的通用平台范围继续延期，M2 仅保留保存版本所需数据基础。

## 2. 本次范围

P0 是我们为交付质量确定的实现目标，**不表示每项都是题面逐字规定**。

| 优先级 | 功能 | 完成定义 |
|---|---|---|
| P0 | 项目与会话 | 创建、输入文字需求、重新打开；评审入口可用，自助注册不是前置条件 |
| P0 | 生成与持续修改 | Pi 在 E2B 对 React/Vite 多文件工程读写、安装、构建；连续两轮追加修改 |
| P0 | 执行状态与失败处理 | 真实工具步骤、有效停止、失败重试；同项目串行执行 |
| P0 | 可交互预览 | 点击和输入有效；刷新、打开新标签、错误提示；简单桌面/窄屏切换 |
| P0 | 持久化与恢复运行 | 服务端保存项目、消息、源码与快照；重新进入可找回，失效沙箱可重建 |
| P0 | 轻量源码视图 | 查看实际生成文件；不做手动编辑或可写终端 |
| P0 | Demo 上线、GitHub 与说明 | 部署工作台可测试；源码含运行说明；准备笔试文档，并按题面 public 要求核对提交链接权限 |
| P1 选定延展 | 固定三角色协作与浏览器检查 | 协调者明确任务，工程师交付版本，独立检查者用 agent-browser 实际操作；失败交回工程师，最多两轮修复 |
| P2 有余量 | 上个版本恢复、源码 ZIP | 基于快照实现便捷操作，不做数据库回退或 GitHub OAuth |
| 延期 | 生成应用通用后端与独立发布 | 不做每应用开通 Supabase、dev/prod、通用迁移、Cloud 管理台或永久域名发布 |
| 延期 | 完整编辑与团队能力 | Visual Editor、素材库、手动代码编辑、浏览器接管、Remix、团队管理、计费 |
| 延期 | M3/M4 通用平台 | 任意建队/角色配置、跨团队路由、Research、Race、连接器、应用内模型市场、Mobile、Video、Analytics、SEO、Ads |

P1 是我们主动选择的一个连贯延展，不是原题无条件硬门槛。它将真实分工、实际试用和修复连在一起，不宣称市场首创。角色具有独立上下文和服务端限制的工具权限，不能只切换头像。用户看到交接与简短结果，无需阅读需求证据报告。Multica 仅作设计参考，不作为源码依赖。

生成应用业务数据库不是 P0。若示例使用浏览器本地存储，须说明局限，不能称为 Cloud；平台项目和源码仍服务端持久化。图片、语音、PDF、Figma、多模板与模型排行榜不进入本次承诺。UI 不放无实际作用的入口。

## 3. 技术收敛

| 部分 | 本次采用 |
|---|---|
| 工作台 | Next + React + TypeScript + Tailwind/shadcn，按需复用 AI Elements |
| Agent | Pi 单框架；P1 三个角色独立 session 与工具集合，共用可配置默认模型 |
| 代码与运行 | E2B，一个 React/Vite 多文件模板 |
| API/任务 | 常驻 Fastify 服务，进程内任务，SSE 状态；单实例并发上限 |
| 平台数据 | Supabase Postgres/Storage 保存项目、会话、源码；最小身份与归属检查 |
| 延展浏览器 | agent-browser 由检查者调用，观察结果结构化交回工程师；暂不引入 Midscene |
| 部署 | 工作台与常驻 API 部署到支持相应运行方式的平台；生成应用在 E2B 预览 |

版本沿用长期蓝图研究基线，集成通过后锁定。暂缓 BullMQ/Valkey、通用 checkpoint/fencing/Outbox、Platform Kit、Dyad tagger、PTY、完整可观测平台；保留运行日志和任务预算。

状态和事件持久化；服务重启将遗留任务标为中断，从已保存结果重新发起，不承诺透明续跑。iframe 与 Agent 的 Chrome 是不同会话，检查目标和身份明确绑定；没有 stream 时不声称同屏接管。

保留凭据隔离、生成代码沙箱、项目归属检查、并发与额度限制、真实失败状态，以及源码独立于沙箱保存。评审可用受限账号，无需开发完整注册与团队系统。

## 4. 实施顺序与时间控制

按实际剩余时间安排，不从当前时刻重新倒数 48 小时。

1. 先验证模型、E2B、远程生成与预览，并部署可通信的工作台/API 骨架，尽早发现线上运行问题。
2. 完成聊天、生成、预览、连续修改、保存和重新打开这条 P0 主流程。
3. 完成固定小队的任务交接、浏览器操作与有限修复，不展开通用团队或测试平台。
4. 使用两个不同需求走查，验证取消、失败、刷新，完善界面和交付说明。

至少为联调与交付留下实际剩余工作时间的 20%。远程生成未通时暂停可选 UI；上线主流程未通过时 P2 全部取消。主流程稳定优先于直播、独立应用发布和额外后端。

## 5. 演示与交付声明

演示从新需求开始：生成带表单/筛选的 Web 应用 → 实际操作 → 查看源码 → 追加修改 → 浏览器检查与修复 → 重新打开继续使用。再换一个需求，证明不是预制成品切换。

工作台地址与生成应用的临时预览地址分开标明；项目资产持久化不等于 E2B URL 永久托管。说明文档列出已完成能力及未实现的 Atoms 功能。

当前只有研究和规划，尚未实现或部署产品。[完整蓝图](implementation-blueprint.md)仅作以后扩展参考。
